## 6. 本轮实测抓出的 4 个真实缺陷（全部已修）

> 这一节是本次验证最有价值的部分：下面每一条都是**先看到运行时现象**，再定位、修复、复验的。

### 6.1 跨分类重复商品没有被去重（严重）

* **现象**：放回旧单文件后，日志显示「12 个分类 / 62 件商品 / 去重 3 条」——
  而离线脚本按「全局去重」算出来应该是 44 条。`44` 与 `62` 不一致。
* **根因**：第一版 `mergeInto()` 的判重表是**每个分类一张**（`PendingCategory.items`），
  所以只有「同一个分类内」的重复才会被发现；`minecraft:stone` 分别落在 `blocks` 与 `stone` 两个分类时被当成两件商品。
* **后果**：同一物品在两个页签各卖一份、两处库存各算各的（玩家视角就是「同一个东西两个价」）。
* **修复**：`DedupRegistry` 全局判重（跨文件、跨分类），冲突时把条目的归属从低优先级分类**转移**到高优先级分类。
* **复验**：旧单文件 + 新默认目录共存 → `9 个文件 → 12 个分类 / 44 件商品；去重丢弃 21 条`，
  日志逐条给出取舍（例如 `minecraft:torch` 从旧 `misc`(30) 转移到 `building`(60)）。

### 6.2 `custom_name` / `lore` 里带 `#` 会让整条商品被跳过

* **现象**：10000 条压力配置**全部**被跳过（`跳过 10000 条`），报错是
  `MalformedJsonException: Use JsonReader.setLenient(true) ... missed input: {"minecraft:custom_name":"压力测试 #1"}`。
* **根因**（读原版源码确认）：`custom_name` / `item_name` / `lore` 用的是
  `ComponentSerialization.FLAT_CODEC` —— 值是**字符串**，而且这个字符串会被
  `JsonParser.parseString`（lenient）**再当成一个 JSON 文档解析一次**。
  Gson 把 `#`（以及 `= / ; { } [ ]` 等）视为非法字面量字符，于是「名字里带个 #」直接抛异常。
  另一个反直觉的点：直接写成 `{"text": "..."}` 对象也不行，FLAT_CODEC 会报 `Not a string`。
* **修复**：解析前统一规范化 —— 字符串能当 JSON 文档解析就原样保留；
  不能（含 `#` 等）就包成 `{"text": "..."}` 的 JSON 文档字符串；直接写成对象 / 数组则序列化成 JSON 文档字符串。
  于是**裸文本 / JSON 文本组件字符串 / 组件对象三种写法都能用**。
* **复验**：`先前的 10000 条压力配置` 全部加载成功；默认模板里也特意给纪念胸甲加了
  `"minecraft:lore": ["深索币官方发售 #001", ...]`，开箱即用地覆盖这条路径。

### 6.3 `/bmcs stock set` 的放量会被下一次重载悄悄改回配置值

* **现象**：`bmcs stock set weapons_tools.1 5`（配置里是 4）→ `/bmcs reload` → 又变回 4；
  重启后也是 4。
* **根因**：`syncWithConfig()` 每次都执行 `min(现有值, 配置初始值)`，无法区分
  「管理员手动放量」与「玩家卖回导致的补货」。
* **修复**：SavedData 升到 v2，额外记录「上次看到的配置初始值」：
  上限没变 → 保留当前值；上限变了 → 夹到新上限；旧存档（无上限记录）→ 保留不夹取。
  `restock` 的上限改为 `max(配置值, 当前值)`，避免「玩家卖回一件反而把管理员放量冲掉」。
* **复验**：`set 9`（上限 4）→ `reload` → 仍为 9；
  把配置上限 4 改成 2 → 日志「配置上限变化，已收紧 1 项限量商品的剩余库存」且值变为 2；
  重启后仍为 2；另一件商品的值（3）跨两次重启保持不变。

### 6.4 系统性写错的配置会刷爆日志

* **现象**：一份 10000 条全部写错的配置，把 10000 行「条目 + 原始 JSON」写进日志，
  `run/server-run7.log` 涨到 **10 MB**，正常信息全被淹没。
* **修复**：逐条报错 / 告警统一走 `logEntry(...)`，只打印前 40 条，之后折叠成一行提示
  （总数仍由「本次加载跳过 N 条」汇总）。
* **复验**：造一个 200 条全部非法的文件 → 每个加载轮次只出现 **40 条明细 + 1 行折叠提示**，
  且分类因为一条都没剩下而被自动隐藏（日志：「以下分类没有任何可用商品…已不显示：[badtests]」），
  其余 44 件商品不受影响。

## 7. 容错实测

| 场景 | 做法 | 结果 |
|---|---|---|
| 语法错误 | 写入半截 JSON `90-bad-syntax.json` | `配置文件解析失败，已跳过该文件`，其余 9 个文件照常加载，商店不清空 |
| UTF-8 BOM | 用 PowerShell `Set-Content -Encoding utf8` 写文件（带 `EF BB BF`） | 正常解析（解析前剔除 BOM）；该文件里的 `minecraft:apple` 参与去重并被更高优先级的 `food` 分类占用 |
| 超限文件 | 写入 11,534,385 字节的 JSON | `配置文件过大（11534385 字节 > 上限 10485760 字节），已拒绝加载`，商店不受影响 |
| 非法条目 | `minecraft:not_a_real_item` / `price: 0` | 两条精确报错并各自跳过，`跳过 2 条`，其余 62 条正常 |
| 卖价高于买价 | `sell_price > price` | 告警并压回 `price`（防刷钱） |
| `display_name` | 旧单文件里每条都带 `display_name` | 每条告警「字段已被忽略」，名字仍由游戏本地化提供，条目正常上架 |
| 目录里一个可读 JSON 都没有 | — | 保留上一份可用数据并给出警告，不会把商店清空（见 `ShopConfig.load`） |


* 重启后**不回到配置初始值**，且配置上限没变时不会夹取；
* 监听线程是守护线程，关服时显式 `close()`（日志确认）。

## 10. 未能验证的部分（如实说明）

1. **客户端 GUI 的视觉效果**：本机无显示环境（`runClient` 需要 OpenGL），
   因此界面只做了「API 签名逐一核对 + 虚拟滚动几何离线自检 + 结构与文案静态检查」，没有截图。
   界面的可滚动语义是按 FTB Library 2101.1.37 的**反编译源码**实现的
   （`PanelScrollBar` 用 `panel.getContentHeight() - panel.getHeight()` 当上限、`onMoved()` 调 `panel.setScrollY()`）。
2. **真实买卖交易**（`ShopActionPayload` 的 BUY/SELL 全流程）：需要客户端按键/点击触发，
   无客户端时无法发起。本轮验证覆盖了它依赖的服务端状态（库存读写、目录版本、余额附件、回滚路径的静态检查），
   以及交易后的增量补丁组装（`debug sync` 走的就是同一条组装路径）。
3. **键位与侧边栏的实际点击**：同上，需要真实客户端。已按 1.21.1 的真实 API（`RegisterKeyMappingsEvent`、
   `ClientTickEvent.Post`、`KeyConflictContext.IN_GAME`、`CustomClickEvent.EVENT`）逐行核对，
   并确认默认键 **O(79)** 在原版 `Options` 的全部默认绑定里未被占用。
4. **多人并发抢购**：未做双客户端压测；超卖由 `ShopStockManager.consume` 的「先校验后扣减 + 主线程」保证，
   属于设计论证而非实测。

## 附：上一轮结论（单文件配置版本，仍然成立）

* `gradlew.bat build` 成功；专用服务器两次启动 + 一次优雅停止，日志无 ERROR。
* 运行时抓到并修复缺陷：裸 `JsonOps` 解析配置会**静默丢弃附魔**（`Can't access registry ResourceKey[...enchantment]`），
  改为 `RegistryOps.create(JsonOps.INSTANCE, registryAccess())` + 严格 `result()` 后，
  日志正确输出 `组件商品 combat.2 = 深索纪念胸甲（附魔 2 项）`。
* 库存持久化：`bmcs stock set combat.1 3` → 重启后 `list` 仍为 3（不回滚成配置值 4）。
* 侧边栏 JSON schema 用**真实 FTB class 常量池**机器校验（挡住 `group`/`x` 这类旧 schema 字段）。
